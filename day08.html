🕵️ Mini OSINT Report: Passive Recon on X.com (Twitter)

Date: March 8, 2025

Target: X.com (Twitter)

1️⃣ Domain Information

🔹 WHOIS Lookup:

  • Domain: X.com
  • Registrar: MarkMonitor Inc.
  • Creation Date: 1993-03-04
  • Updated Date: 2023-08-16
  • Expiration Date: 2033-03-05
  • Name Servers:
    • ns1.p34.dynect.net
    • ns2.p34.dynect.net
    • ns3.p34.dynect.net
    • ns4.p34.dynect.net

📌 Key Finding: The domain is very old (1993), originally owned by Elon Musk for PayPal before being repurposed for Twitter in 2023.

2️⃣ Subdomain Enumeration

Method: Certificate Transparency Logs (crt.sh)

🔹 Discovered Subdomains:

  • api.x.com → Twitter API
  • mobile.x.com → Mobile version
  • help.x.com → Help center
  • ads.x.com → Ad management
  • careers.x.com → Job portal
  • dev.x.com → Developer resources
  • cdn.x.com → Content delivery

📌 Key Finding:

  • The API subdomain (api.x.com) could reveal interesting endpoints.
  • Careers and help pages may expose internal job postings or public documentation.

3️⃣ Technology Fingerprinting

Tool Used: Wappalyzer

  • Web Server: Nginx
  • CDN: Akamai, Fastly
  • Frontend: React, Bootstrap
  • Security Headers: CSP, HSTS, X-Frame-Options
  • Tracking Services: Google Analytics, Facebook Pixel

📌 Key Finding:

  • Uses multiple CDNs (likely for load balancing and DDoS protection).
  • Strong security headers, reducing attack surface.

4️⃣ Google Dorking

Dork Used: site:x.com filetype:pdf

🔹 Discovered Public Files:

  • https://help.x.com/en/pdfs/privacy-policy.pdf
  • https://careers.x.com/documents/employee-handbook.pdf
  • https://ads.x.com/marketing-guidelines.pdf

📌 Key Finding: Some public files are accessible, which may provide insights into company policies and guidelines.

🔹 Dork Used: site:x.com inurl:admin

  • No exposed admin panels found.
  • Likely well-protected against directory browsing.

5️⃣ Social Media & Employee Data

Tool Used: theHarvester, hunter.io

🔹 Discovered Emails:

  • security@x.com (Likely used for vulnerability reports)
  • support@x.com (General inquiries)
  • pr@x.com (Press & media)

📌 Key Finding: No direct employee emails found, indicating good email security practices.

🔹 LinkedIn Recon:

  • Public employee profiles from Twitter/X found.
  • Some mention internal tools & roles, which could be useful for social engineering.

6️⃣ Historical Data & Exposed Files

Tool Used: Wayback Machine (waybackurls)

🔹 Discovered Old URLs:

  • https://x.com/old-login (Defunct, redirects to main site)
  • https://blog.x.com/twitter-acquisition-2023/
  • https://api.x.com/v1/deprecated-endpoints/

📌 Key Finding:

  • Some old API endpoints were publicly listed but now return 404 errors.
  • Old blog posts confirm timeline of Twitter rebranding.

7️⃣ Public Exposure on Shodan

Query Used: X.com

🔹 Exposed Services:

  • Akamai Edge Servers detected
  • No direct exposed ports/services on Twitter-owned infrastructure

📌 Key Finding:

  • Uses Akamai for security & DDoS protection, reducing attack surface.
  • No publicly exposed login portals or databases.

📝 Summary of Findings

✅ Secure Areas:

  • Strong CDN security & DDoS protection.
  • No major exposed admin panels or services.
  • Bug bounty & security contacts available for responsible disclosure.

⚠️ Potential Risks:

  • Old API endpoints listed in historical archives (need further investigation).
  • Public employee job postings could reveal internal structures.
  • Publicly available PDFs & documents may contain insights into internal policies.

📌 Next Steps:

  • Analyze GitHub repositories for exposed credentials.
  • Monitor Google Dorking for leaked data (site:x.com password).
  • Check API documentation for security misconfigurations.

Challenge #1

🕵️ OSINT Challenge: Passive Recon on X.com (Twitter)

📝 Challenge Scenario

Your team is working as security researchers. You’ve been assigned to analyze X.com (Twitter) using passive OSINT techniques. Your goal is to collect as much publicly available information as possible without actively interacting with the target (no direct scanning, brute force, or intrusion).

🛑 Rules:

  • Only use public data sources.
  • No brute forcing, scanning, or exploiting allowed.
  • Only passive recon tools like Google Dorks, WHOIS, Shodan, and Wayback Machine.

🕵️ Tasks & Questions

📌 Task 1: Domain Intelligence

  1. What is the WHOIS registration information for X.com?
    • (Bonus: What year was the domain originally registered?)
  1. Which name servers are responsible for X.com?
    • (Bonus: Does it use cloud-based protection?)

🔹 Tools to Use: WHOIS lookup (whois x.com), who.is, ICANN Lookup

📌 Task 2: Subdomain Discovery

  1. Find at least 3 subdomains of X.com.
    • (Bonus: Identify one that serves APIs.)

🔹 Tools to Use:

  • crt.sh (Certificate Transparency logs)
  • subdomainfinder.c99.nl (Subdomain search)
  • SecurityTrails

📌 Task 3: Technology Fingerprinting

  1. What server and technologies does X.com use?
    • (Bonus: Identify the CDN provider.)

🔹 Tools to Use:

  • Wappalyzer
  • whatweb x.com (CLI tool)
  • BuiltWith

📌 Task 4: Google Dorking

  1. Use Google Dorks to find publicly available files.
    • Can you find an X.com policy document or employee handbook?
    • (Bonus: Find an old or cached page that is no longer live.)

🔹 Useful Google Dorks:

site:x.com filetype:pdf
site:x.com inurl:admin
site:x.com intext:"confidential"
  • Use Google Advanced Search Operators to refine results.

📌 Task 5: Employee & Social Media Intelligence

  1. Find at least 2 email addresses related to X.com.
    • (Bonus: Identify an official security contact.)
  1. Find a LinkedIn profile of someone working at X.com.
    • (Bonus: Identify what team they are part of.)

🔹 Tools to Use:

  • Hunter.io (Email discovery)
  • theHarvester -d x.com -b linkedin (CLI)
  • LinkedIn search: site:linkedin.com "X.com" AND "email"

📌 Task 6: Historical Data & Leaks

  1. Find old pages or API endpoints of X.com using the Wayback Machine.
    • (Bonus: Identify an outdated API endpoint.)

🔹 Tools to Use:

  • Wayback Machine
  • waybackurls x.com (CLI)

📌 Task 7: Exposure Check

  1. Check if X.com has any exposed services or security misconfigurations.
    • (Bonus: Does it have DDoS protection enabled?)

🔹 Tools to Use:

  • Shodan (shodan.io/search?query=x.com)
  • Censys

🎯 Learning Outcome

  • Understand real-world OSINT techniques used in pentesting & bug bounties
  • Learn how to gather intelligence ethically
  • Improve Google Dorking & data analysis skills
