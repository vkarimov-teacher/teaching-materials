TCP scanning

TCP scanning is a technique used to determine the status of TCP ports on a target system. This process helps in identifying open, closed, or filtered ports, which can provide valuable information about the services running on the target. Here’s a detailed explanation of the TCP scan process:

1. Understanding TCP Handshake

Before diving into TCP scanning, it’s important to understand the TCP handshake, which is the foundation of how TCP connections are established:

  • SYN: The client sends a SYN (synchronize) packet to the server to initiate a connection.
  • SYN-ACK: The server responds with a SYN-ACK (synchronize-acknowledge) packet if the port is open and it’s willing to establish a connection.
  • ACK: The client sends an ACK (acknowledge) packet to establish the connection fully.

2. Types of TCP Scans

There are several types of TCP scans, each with its unique approach and purpose:

  • SYN Scan (Half-Open Scan)
  • Connect Scan
  • ACK Scan
  • FIN Scan
  • Xmas Scan
  • Null Scan

3. Detailed Steps for Common TCP Scans

SYN Scan (Half-Open Scan)

Step-by-Step Process:

  1. Send SYN Packet: The scanner sends a SYN packet to the target port.
  1. Receive Response:
    • SYN-ACK: If the port is open, the target responds with a SYN-ACK packet.
    • RST: If the port is closed, the target responds with an RST (reset) packet.
  1. Send RST Packet: After receiving a SYN-ACK, the scanner immediately sends an RST packet to tear down the connection before it's fully established. This is why it’s called a half-open scan.
  1. Interpret Results: Based on the responses, the scanner determines the status of the port:
    • Open: SYN-ACK received.
    • Closed: RST received.
    • Filtered: No response or an ICMP unreachable message received.

Connect Scan

Step-by-Step Process:

  1. Send SYN Packet: The scanner sends a SYN packet to the target port.
  1. Receive SYN-ACK: If the port is open, the target responds with a SYN-ACK packet.
  1. Send ACK Packet: The scanner sends an ACK packet, completing the TCP handshake.
  1. Terminate Connection: The scanner sends an RST packet to close the connection.
  1. Interpret Results: Based on the responses, the scanner determines the status of the port:
    • Open: Full TCP handshake completed.
    • Closed: RST received.
    • Filtered: No response or an ICMP unreachable message received.

ACK Scan

Step-by-Step Process:

  1. Send ACK Packet: The scanner sends an ACK packet to the target port.
  1. Receive Response:
    • RST: If the port is unfiltered, the target responds with an RST packet.
    • No Response or ICMP Error: If the port is filtered, the target either does not respond or sends an ICMP unreachable message.
  1. Interpret Results: Based on the responses, the scanner determines the status of the port:
    • Unfiltered: RST received.
    • Filtered: No response or an ICMP unreachable message received.

FIN, Xmas, and Null Scans

These scans are designed to evade simple stateless firewall and packet filtering rules. They work on the principle that closed ports must reply with an RST packet, while open ports should ignore the packets.

Step-by-Step Process:

  1. Send FIN/Xmas/Null Packet: The scanner sends a FIN, Xmas (which sets the FIN, PSH, and URG flags), or Null packet (with no flags set) to the target port.
  1. Receive Response:
    • RST: If the port is closed, the target responds with an RST packet.
    • No Response: If the port is open, the target ignores the packet.
  1. Interpret Results: Based on the responses, the scanner determines the status of the port:
    • Open: No response.
    • Closed: RST received.
    • Filtered: No response or an ICMP unreachable message received.

4. Tools for TCP Scanning

Common tools used for TCP scanning include:

  • Nmap: Widely used for various types of network scanning.
  • Zenmap: The graphical interface for Nmap.
  • Masscan: Known for its speed in scanning large networks.

5. Ethical Considerations

  • Always obtain proper authorization before performing any scans.
  • Be aware of the legal implications and potential consequences of scanning without permission.
  • Follow best practices and ethical guidelines to ensure responsible use of scanning techniques.

Example of Performing a SYN Scan with Nmap

nmap -sS <target IP>

This command performs a SYN scan (-sS) on the specified target IP address.

Example of Performing a Connect Scan with Nmap

nmap -sT <target IP>

This command performs a connect scan (-sT) on the specified target IP address.

By understanding and correctly implementing these TCP scanning techniques, cybersecurity professionals can effectively assess network security and identify potential vulnerabilities.
